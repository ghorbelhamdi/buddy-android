## Setup in detail

| Step | What happens |
|---|---|
| Choose your agent | **Claude Code** (recommended), **Codex**, **OpenCode** (free models, no account), **Antigravity** (your Google account), **Grok** (your Grok account; sign in with Google or X), or Claude Code and Codex together |
| Accessibility | Turn on *Buddy assistant*. Greyed out ("Restricted setting")? App info → ⋮ → **Allow restricted settings**, then try again |
| Install and sign in | One tap installs your agent in Buddy's Linux (Claude Code about 235 MB, Codex about 150 MB, OpenCode about 230 MB, Antigravity about 200 MB, Grok about 170 MB; use Wi-Fi). OpenCode needs no sign-in; its providers can be connected later with **Connect a provider**, which runs `opencode auth login` in Buddy's terminal. For the others, **Sign in**: your browser opens, you approve, and Buddy comes back by itself. For Claude and Antigravity, Buddy picks the one-time code off the confirmation page for you (Antigravity waits about a minute for it). For Grok, the page opens with a one-time code: check it, confirm, and Buddy comes back by itself. No browser on this phone you want to use? **Sign in on another device** (Claude, Antigravity: a link to open anywhere; Grok: the link and its code) or **Sign in with a code** (Codex) For Claude Code there's also **Use a token**: paste the token that `claude setup-token` prints on a computer (it starts `sk-ant-oat`). It covers chats; voice input and Remote Control need the full sign-in. Sign out removes it. |
| Keep it running | Battery: unrestricted for Buddy |
| Try it | A first chat with a ready-made prompt |

**Android blocked the install?** Play Protect may say *"App blocked to protect your device"* for apps that use Accessibility and come from a browser: tap **More details → Install anyway** (or install from a file manager). In some countries Play Protect's stricter mode (enhanced fraud protection) shows no *Install anyway*: it blocks any sideloaded app that uses accessibility or notification access, from a browser, a messaging app or a file manager. Then turn off **Play Store → Play Protect → ⚙ → Scan apps with Play Protect** just for the install and turn it back on afterwards, or install from a computer with `adb install buddy.apk`. On Android 13+, if *Buddy assistant* is greyed out in Accessibility, open App info → ⋮ → **Allow restricted settings** first.

## Updating

**Ask Buddy:** *"Is there a Buddy update?"* or *"Update yourself."* The agent checks the latest release, tells you what's new, and with your OK downloads `buddy.apk` from this repo's releases and opens Android's installer; you tap **Update**.

**Automatic updates with [Obtainium](https://obtainium.imranr.dev)** (free, open source; it checks GitHub for you and installs new versions):
1. Install Obtainium (from its website, F-Droid or IzzyOnDroid).
2. In Obtainium, tap **Add App** and paste `https://github.com/ghorbelhamdi/buddy-android`, then **Add**.
3. Each release has two identical APKs (`buddy.apk` and `buddy-vX.Y.Z.apk`). If Obtainium asks which one, pick `buddy.apk`. To never be asked, set **Filter APKs by regular expression** to `^buddy\.apk$` in the app's settings in Obtainium.
4. Obtainium now notifies you when a new version is out; tap **Update** and confirm Android's installer (the first time, allow Obtainium to install apps).

**From F-Droid:** Buddy is on [F-Droid](https://f-droid.org/packages/app.buddy.assistant/), and the F-Droid app updates it for you. F-Droid builds each version itself, so a new one arrives there some days after the GitHub release. Its build is the same app signed with the same key, minus the built-in updater, so you can switch between the two without reinstalling.

**By hand:** open the [latest `buddy.apk`](https://github.com/ghorbelhamdi/buddy-android/releases/latest/download/buddy.apk) on the phone and install it over the current one. To get an email for each new version, sign in to GitHub and choose **Watch → Custom → Releases** on the repository.

**The agents** (Claude Code, Codex, OpenCode, Antigravity, Grok) update separately: Settings → the agent → **Check for updates**. An OpenCode 1.x install gets **Update to OpenCode 2** there; your connected providers are kept.

## Using Buddy

The app has three tabs: **Chats**, **Sessions** and **Settings**.

- **Chats:** start one with **New chat** (Claude Code, Codex, OpenCode, Antigravity or Grok; agents that aren't set up are greyed out), tap a chat to open it, long-press to **rename**, **pin** to the top, **archive** or delete it. Archived chats move to a folded **Archived** section at the bottom, out of the bubble and sharing; their scheduled tasks keep running, and writing in one brings it back. There's no limit on how many chats you keep. Several chats can work at the same time. Replies and your own messages show Markdown (bold, lists, `code`, links). A table in a reply is shown as one, with a heading row; a table wider than the screen scrolls sideways. A selection can't reach past a table, so a small copy icon under each reply copies all of it, in the chat and in the bubble (there a long press on the reply does the same), and a long press on a table in the chat copies that table. A long chat opens on its latest messages; **Show earlier messages** at the top loads more (Buddy keeps 2,000 per chat). A chat that an older Buddy cut short offers **Load earlier messages**, which fetches its start from the agent's own record.
- **Models:** tap the chip under a chat's title to pick the model for that chat (Opus, Sonnet, Haiku, Fable, Codex's own list, OpenCode's models including the free ones, Antigravity's and Grok's lists, or any model name). The conversation continues with the new model. The lists and each model's effort levels come from the agents themselves, so a new model shows up without a Buddy update. To start every chat on a model of your choice, set it in Settings → **Default model**.
- **Linux tools**: the chip next to the model shows whether the agent may work in Buddy's Linux in that chat (run commands, install packages, edit files, build apps); tap it to switch. **New chat** has the same switch. See [Linux tools](#linux-tools-building-apps).
- **Photos and files:** tap the paperclip to take a photo, pick photos, or attach any file up to 25 MB.
- **Voice:** tap the mic to talk; the box turns into a recording bar (✕ cancel, live waveform, ↑ send). Choose the engine in Settings → Voice: the **phone's** recognizer, **Claude** (Claude Code's own dictation, on your Claude plan) or **ChatGPT** (ChatGPT's voice through Codex, on your ChatGPT plan; any language, even mixed). Claude and ChatGPT are greyed out until Claude Code or Codex is signed in. Pick your languages there; long-press the mic to switch.
- **As your phone's assistant:** pick Buddy in Android's Settings → Apps → Default apps → Digital assistant app. Long-pressing the power button (or your phone's assistant gesture) then starts Buddy listening beside the bubble (or, if you choose Live voice under Settings → Voice, a live voice conversation); when a task is running or waiting for you, it opens the chat instead. Nothing listens before that: there's no wake word. With **Only when the phone is unlocked** on (Settings → Voice), the gesture does nothing on the lock screen or in standby. Holding the bubble offers both too: **Talk** for one request, **Live voice** for a spoken conversation in a new chat with the agent set under Settings → Voice → **Live voice uses** (your default agent unless you pick another; with **Continue the last chat** on, it picks up your latest chat with that agent instead; Codex must be signed in; during the call, tapping the bubble opens that chat), and **End live voice** while one is on.
- **Read aloud:** the speaker button reads replies, in the phone's voice or in **ChatGPT's voice** (Juniper, Maple, Ember, Cove: Settings → Voice → Voice output).
- **Add instructions while it works:** type or talk while a task runs; the agent gets it at its next step, without stopping.
- **Tool calls** fold into one "N tool calls" line you can open.
- **Pause media while reading aloud** (Settings → Voice, off at first): music or a video that's playing is paused while Buddy reads a reply, and starts again afterwards. Buddy restarts only what it paused, and not when you changed playback in the meantime. It needs notification access (that is how Buddy sees which app is playing); without it nothing is paused.
- **Cards by voice:** with **Read replies aloud** on (Settings → Voice), Buddy also reads approval cards and questions aloud. Turn on **Answer cards by voice** below it and Buddy listens after reading: say "approve" or "deny", or for a question the option you want (anything else is taken as your own answer). If it hears neither approve nor deny it asks again, twice at most, and never guesses. It doesn't listen while the phone is locked, where Approve takes your fingerprint. Anyone within earshot could answer, so it's off unless you turn it on.
- **Search:** the magnifier on the Chats screen finds chats by their title and by what you and the agents said in them, archived ones too, and shows where the words are. A tap opens the chat at the newest message that has them, tinted for a moment. Incognito chats are left out. Nothing leaves the phone for it.
- **Notification rules:** Settings → Safety and approvals → Notification rules. A rule picks an app, optionally who it's from and words it contains, and says what the agent should do; the agent gets that instruction with the notification, in a chat of its own per conversation (so it remembers what it answered before). It can reply through the notification's own Reply field without opening the app. Each rule picks its agent and model (a smaller model is quicker and uses less of your plan). Before acting, a rule either asks you as usual or uses a **countdown** (10 s to 5 min): the approval card approves itself unless you tap to stop it. The third choice, **Don't ask**, sends the message right away with no card. Only sending a message can be approved in these two ways, and only after a second AI has checked it against your rule (the Smart reviewer: Haiku by default, or the model you pick in App permissions); if it objects, the card waits for you. If you don't answer within a minute (or the phone is locked), the reply goes to **Waiting for you** (a notification and a banner on the Chats screen), where you send, edit or skip it later; nothing else waits on you meanwhile. A reply is held back when the person writes again before it's sent, and the next run answers everything in one reply. Without internet, rules wait and start when the connection is back. When Android hides a chat's notification from apps with notification access (it does when a message looks like a one-time code), a rule can't read it: Recent activity and a quiet notification say so, and the rule picks up again once the notification is readable (open the chat). Recent activity is listed on the rules screen, and each run ends with a quiet notification saying what it did. Buddy needs notification access for this (it asks first); notifications no rule matches are ignored (except that a call's notification pauses an agent that's using the phone: for that only its category is looked at).
- **A rule from a chat:** ask an agent in a chat to watch a notification ("when Sam writes on WhatsApp, answer that I'm driving"). It proposes the rule on a card, with the app, what to match and the instruction; nothing is added unless you approve. Each match then comes into that chat, which keeps its own agent and model, and the run works as a notification rule's run does. The rule starts on asking before acting; countdown and *Don't ask* are yours to switch on, and Notification rules lists it with the chat it goes to.
- **Scheduled tasks:** a chat's options → **Schedule**: a message Buddy sends into that chat on its own, every day, on weekdays or on days you pick, at one time or several times of the day (**+** adds a time, ✕ removes one; "open the app and do today's check-in"). It runs with the chat's agent and options, also with the phone locked; approval cards still wait for you, and if it needs the screen it asks you to unlock (or, with **Wake the phone for this task**, turns the screen on). A run is skipped when the chat is still working on the last one. When a time comes while an earlier one of the same chat still waits for Buddy to be free, the two become one run. Agents can also schedule a message to themselves ("check the price again tomorrow at 9"): waiting messages show above the chat, tap one to read it, ✕ to cancel it.
- **Share to Buddy:** share a photo, file, link or text from any app and pick **Ask Buddy**: choose a new chat or a recent one, and it opens with the attachment or the text in the message box, ready to send. Nothing is sent on its own.
- **Local models:** to run everything on a model of your own, pick **Local model** in the first-run guide (Settings → the setup card → **Open the step-by-step guide** opens the guide again at any time, starting at the choice of agent). Buddy then installs OpenCode (free, no account) to drive the model and asks for your server: Ollama, LM Studio or llama.cpp on a computer on your network, with its address in place of localhost and no key. OpenCode's chats use that server by default. Later, add a server under Settings → Agents and models → API keys → Add API key; if your default agent can't use it, the setup card says which agent can and switches to it with one tap. An agent is always needed: it is what works with the model, Buddy gives it the phone. Small models (4–8B) only manage simple requests.
- **Models on this phone (Settings → Agents and models):** download a model and Buddy runs it on the phone itself: nothing leaves the phone, and it works without internet. The list has Gemma 4 E2B, Gemma 4 E4B, Qwen3.5 2B and Qwen3.5 4B (all Apache-2.0); each download is checked against its checksum, and the first one also fetches the engine, llama.cpp's official Android build (about 33 MB once installed). **Runs on** picks the chip: on Snapdragon phones the NPU (Snapdragon 8 Gen 2 and newer), the GPU or the CPU, other phones the CPU; **Auto** takes the fastest that starts. **Think before answering** is off: small models answer each step in a second or two without it, and with it a step can take 20 seconds or more. In an OpenCode chat, pick the model under **On this phone** in the model menu. Buddy starts the model when a chat sends it something (the first answer takes a few seconds longer) and stops it after 10 minutes without use. When the phone gets too hot, Buddy stops it and says so. Small models handle simple requests (the battery, a timer, a quick look at an app) and make mistakes on longer tasks.
- **Lite mode (Chat options):** for small models. The agent starts with a short prompt and a dozen phone tools instead of all of them, and loads a group of others when the task needs them (more screen tools, phone info, quick actions like alarms, the background browser, scheduling, advanced). It's on by itself for models on this phone, and a switch for any OpenCode chat. No Linux tools while it's on.
- **Download server (Settings → Agents and models):** where Buddy's Linux, its packages and the agents installed with npm (Codex, OpenCode) come from. Leave it on Default unless installs fail or crawl where you are: almost everywhere, Alpine's and npm's own servers answer from nearby. Where they don't, pick a server in the country: **USTC**, **TUNA** or **Aliyun** in mainland China (npm from npmmirror), **Yandex** in Russia, **Mobinhost** in Iran (npm from a mirror there), or **Custom** with the address of any Alpine mirror (Alpine lists them at mirrors.alpinelinux.org) and, if you have one, an npm registry. A mirror serves the same Alpine files: the system image is still checked against its SHA-256 and every package's signature is checked. For npm packages the registry you choose vouches for them. With another server, Buddy's Linux also asks your network's own DNS servers first. It applies to a Linux that is already installed too. The agents' own services (Claude, ChatGPT, Gemini, Grok) are not mirrored: where they are blocked, use an API service or a local model.
- **API keys (Settings → Agents and models → API keys):** add other services' models, next to your plans or instead of them. Pick DeepSeek, OpenRouter, Anthropic or OpenAI from the Service menu, which fills in the addresses, or choose Custom and enter the service's Anthropic-style address, its OpenAI-style address, or both. Then add the key. When you save, Buddy lists the service's models, with their context size, and keeps the list fresh: a server on your own computer (Ollama, LM Studio, llama.cpp) each time you open a model picker, so a model you just pulled shows up, and online services every 10 minutes. Claude Code uses the Anthropic-style address, Codex and OpenCode the OpenAI-style one (Codex needs OpenAI's Responses API there), and OpenCode can also use the Anthropic-style one. **Check now** is optional: it sends a very small test request (it may use a tiny bit of API credit) and shows what the service answered. If something doesn't work, the agent's own error shows in the chat. If the default brain can't use your key, setup says so and offers an agent that can. Each chat picks a model in its model sheet, where each service's models appear under its name; **Default model** sets what a chat on Default uses per agent (its own default, on its plan, one of its own models, or a service's model); the same row is in Settings → Agents and models, for every agent that's signed in. **Choose models** keeps long lists (OpenRouter's) short in the pickers. Buddy tells the agent the model's real context size (from a llama.cpp server on your own network, the size the server runs the model with), and shows only the effort levels the service lists. Use with a key is billed to the key's account. Keys are kept encrypted in Buddy's app storage and never go into Buddy's Linux: the agents send their requests to Buddy, which adds the key and passes them on, so no agent or command can read it. Voice input, live voice, Remote Control and the Codex session for the ChatGPT app need the plan itself. A saved service has a **Use this service** switch: off, its key stays on the phone but the model lists don't offer it, an agent that used it by default goes back to its own model, a chat set to one of its models tells you instead of running, and Buddy stops calling it.
- **MCP servers (Settings → Tools and connections → MCP servers):** connect your own MCP servers, and every agent gets their tools next to the phone's. Add a server by its address (https, or http on this phone or your own network) and, if it has one, its key; Buddy asks the server for its tools before saving and lists them with their descriptions. Each server has a **Use this server** switch, and the list can be copied out (without keys) or pasted in as other MCP clients keep it (`mcpServers`). Agents never get a server's address or key: each one talks to Buddy, which passes the call on with the key. Only servers reached over HTTP work; ones that run as a command on a computer don't. These tools act outside the phone, so Buddy's approval cards don't cover them: add only servers you trust. They're left out of a notification rule's run.
- **Phone tools without the screen:** agents can read the clipboard (Buddy asks you every time) and copy to it, set an alarm or start a timer in the Clock app, open the share sheet with a text or a file (you pick the app), save a file from Buddy's Linux to Downloads/Buddy, check the phone's battery, network, time and free storage, open the camera for you to take a photo, and get the phone's location (Buddy asks every time). A notification rule's run can't read the clipboard, share, save files, take photos or get the location. Files can only leave Buddy's Linux from the Linux tools' work folder or a chat's own files.
- **More without the screen:** agents can read your current notifications ("what did I miss?"; needs notification access, and a notification rule's run can't), control what's playing (play, pause, next, volume, what's on), read your calendar (asks for access the first time) and open the Calendar app with a new event filled in for you to save.
- **Calls and text messages (off until you turn them on):** agents can read recent calls (who, when, how long) and SMS (sender, time, read or not, the text). Turn them on in Settings → Tools and connections → Tools. They need background mode set up: Buddy reads them through its helper there, so Buddy itself never asks for, or holds, the SMS or call log permission (with it, Google Play Protect blocks Buddy as harmful). They are read only (nothing is called, sent or deleted), give at most 50 at a time, and a notification rule's run can't use them. Numbers that could be codes (one-time codes, PINs, also order or flight numbers) show as `[code hidden]` unless you turn on **Show codes in SMS**; amounts, dates and years stay. Message text is treated as content, never as instructions, and Buddy's step log doesn't keep it (an agent's reply that quotes a message stays in the chat like any reply).
- **Which tools agents get:** Settings → Tools and connections → **Tools** lists every phone tool with a switch. A tool that's off isn't offered to any agent, and a call to it is refused. **Chat options → Tools** does the same for one chat (its own choices are marked "this chat only"; **Same as Settings** drops them), and a chat's sub-agents follow it. Asking for your OK and asking you a question are always on.
- **Quicker on screen:** agents can do several taps and typing in one go (each step still goes through your approvals, and the batch stops at the first problem or card), wait for something to appear instead of guessing, read a whole long chat or list in one call, and scroll until they find something.
- **Skills (Settings → Tools and connections → Skills):** instructions an agent follows for a kind of task, in the SKILL.md format Claude, ChatGPT and Codex use. Import a .zip, .skill or SKILL.md, or write one; in a chat with Linux tools you can also ask the agent to write one. Claude Code, Codex and OpenCode use a skill when a task fits, or when you type **/** in the message box and pick it (Claude Code chats also offer **/compact** there). They're kept in `~/.agents/skills` in Buddy's Linux, linked into Claude Code's own skills folder.
- **Context:** a Claude Code or Codex chat's model sheet shows how much of the model's context the conversation fills; the chip shows it once it's past half full. **Compact now** (Claude Code) summarizes the conversation to free up room, and the chat says when it's been compacted, by you or on its own.
- **Scheduled (Settings → Background and automation):** every chat's scheduled task, with **Run now** and **Pause**, and the messages and reminders agents scheduled, with ✕ to cancel. A task can be set to **Only tell me when there's news**: when a run finds nothing new it ends without a notification (its reply is still in the chat, and a problem always notifies you). Ask an agent to remind you of something and you get a plain reminder at that time, without the agent running again.
- **View steps:** the "N tool calls" line of a chat has **View steps**: what the agent did on the phone in that chat's last 3 runs, each step with a small picture of the screen after it, its time and the run's outcome. Kept only on the phone, deleted with the chat, never for incognito chats.
- **Cut off?** When Android closes Buddy while an agent is working (an update, low memory), the chat says so and offers **Continue**: the agent checks what's already done and goes on from there.
- **Incognito chats:** a chat's options → **Incognito**: the chat is deleted when Buddy restarts, together with what its agent kept of the conversation.
- **Backup and move (Settings → Backup and about):** one file in Downloads/Buddy with your chats, settings, rules, pictures, skills, the agents' projects (without build folders) and their records of each conversation. Restore it on this phone or another; Buddy restarts. Sign-ins, API keys and Buddy's own tokens aren't in it. A backup is a file from outside, so restoring one can't loosen what agents may do: the safety switches (Linux tools, phone commands, Let agents tap Buddy's screens, the first-setup choice), *never ask* buttons, MCP servers, the download server, custom API addresses and the reviewer stay as they are on this phone; each app gets the stricter of the two phones' choices, so Trust only if this phone trusts it already; *always ask* buttons from both are kept; notification rules that differ from this phone's arrive paused; restored chats start on Ask, and without Linux tools on a phone where new chats start without them; and only the folders a backup holds are unpacked into Buddy's Linux, without links that lead out of them (a link to a program elsewhere in Linux, say, is left out). Its chats, scheduled tasks and skills are taken as they are, so only restore a backup you made.
- **Plan usage:** after a Claude Code turn, Settings shows how much of your Claude plan's 5-hour and weekly limits is used, with their reset times; a chat says so once when either passes 80% and 95%.
- **Runaway tasks:** a run stops after the same action 6 times in a row, so a loop can't use up your plan. Tell the agent to go on if it should. There is no limit on how many actions a task may use; you can stop one any time.
- **When a task ends and you aren't looking** (the phone is locked, or the chat worked in the background and isn't the one on screen), its reply comes as a notification that opens the chat. A long task's and a scheduled one's always do.
- **Check Buddy:** Settings → Backup and about → **Check Buddy** tests each part (accessibility, notification access, battery optimization, Buddy's Linux and helper, the phone tools server, your agent, internet, free space) and offers a fix for what fails. **Copy report** and **Report a bug on GitHub** include versions and results only, never chats, screen text or notifications.
- **Approvals** appear in the chat and in the bubble: **Approve**, **Deny**, or **Change**: type or say what to adjust ("make it 9, add a smiley"), and the agent revises the message, post or email and asks again.
- **Sessions:** every Claude Code, Codex, OpenCode, Antigravity and Grok process in Buddy's Linux, with a Stop button. Recent sessions can be read, or continued in Buddy.
- **Settings:** the setup card on top, then a menu, each entry with its own page: **Agents and models** (default agent, install, sign in and out, API keys, default models, GitHub, download server), **Bubble and chat** (the bubble, whether it hides while Buddy is open, what a tap does, the panel's size), **Voice** (input and output, languages, live voice, reading replies aloud), **Safety and approvals** (app permissions, notification rules, Linux tools in new chats, Buddy's own screens), **Background and automation** (background mode, scheduled tasks, the background browser), **Tools and connections** (MCP servers, skills, the phone tools for other terminals, Remote Control, SSH), **Appearance** (light/dark/system, accent colour: six of Buddy's, your own, or on Android 12+ the phone's own from your wallpaper, surface, and **Buddy's look**: its own face or a picture of yours, best a PNG or WebP with a transparent background, shown on the bubble and next to its replies) and **Backup and about** (backup and move, updates, this guide, Check Buddy).
- **Languages:** Buddy is in English, Arabic, Chinese (Simplified), Dutch, French, German, Hindi, Indonesian, Italian, Japanese, Korean, Polish, Portuguese, Russian, Spanish, Turkish, Ukrainian and Vietnamese. It follows the phone's language; to pick another one for Buddy alone, use Android Settings → Apps → Buddy → Language. The agents answer in whatever language you write in.
- **Terminal:** a real terminal for Buddy's Linux (Sessions → Terminal): tabs, text selection and copy, links, pinch to zoom. Claude Code's, Codex's, OpenCode's, Antigravity's and Grok's own screens run in it.

### Phone tools in your own sessions

Buddy's phone tools are a regular MCP server on the phone (`http://127.0.0.1:8765/mcp`, with a per-install token). Settings → **Phone tools in your own sessions** shows a ready-made command for **Claude Code** (`claude mcp add-json …`), **Codex** (`codex mcp add …`), **OpenCode** (an `OPENCODE_CONFIG_CONTENT` line for `~/.bashrc`) **Antigravity** (`agy mcp add …`) and **Grok** (`grok mcp add …`), with a Copy button. All but Antigravity's set a 10-minute tool timeout, so an approval card can wait for you (the agents' default is a minute). Run it once in any terminal on the phone (Termux, for example), and every session of that agent gets the `phone` tools, even without the bubble. The token is masked on screen. For MCP clients that can only start a server as a command, [mcp-bridge](../mcp-bridge) passes stdio on to Buddy.

### Remote Control: a Claude Code session in your Claude app

Settings → **Remote Control → Claude Code session** keeps a Claude Code session with [Remote Control](https://docs.claude.com/en/docs/claude-code) running inside Buddy. It appears as **"Buddy"** in the Claude app's Code sessions, on this phone or anywhere else, and it has the phone tools. Buddy restarts it if it stops and continues the same conversation after an update.

### Codex session in the ChatGPT app

Settings → **Remote Control → Codex session** keeps Codex's app-server with remote control running inside Buddy, with the phone tools, so you can use it from the ChatGPT app (Codex) on this phone or on a computer. **Pair a device** shows a one-time code (it works once, for about 10 minutes) to enter in ChatGPT: in Codex on a phone, or under Settings → Connections → Control other devices on a computer. Buddy shows up there as **"localhost"**, because Codex names a host after the system's hostname. Codex keeps its own settings, so you pick each chat's permission in ChatGPT. Codex's sandbox can't run inside Buddy's Linux, so with Default permissions Codex asks before running each command outside it (with Full access it doesn't ask). Buddy restarts the server if it stops, and pairings are kept.

### SSH from Termux

Settings → **Remote Control → SSH from Termux** runs an SSH server (OpenSSH) inside Buddy's Linux, so you can work in it from Termux: `ssh buddy`, `scp`, `sftp`, port forwarding. It listens on `127.0.0.1:8767` only, so only apps on this phone can reach it (from a computer, go through `adb forward tcp:8767 tcp:8767`), and it takes keys only, no passwords. **Copy command** gives a Termux command that makes a key if Termux has none, sends it to Buddy with a one-time code (it works once, within 10 minutes) and adds `Host buddy` to `~/.ssh/config`. Run it once; from then on, `ssh buddy` in Termux opens Buddy's Linux. Buddy keeps the server running, also after an update, until you switch it off.

### When an agent is using your phone

As soon as an agent starts operating the phone, Buddy makes it obvious so you know not to touch it: the bubble turns into a solid **"Using your phone"** pill that also names the step ("Using your phone · Tapping “Send”") (hold the bubble for **Pause** or **Stop task**; it shows even if you've hidden the bubble), and a status-bar notification appears (a Live Update chip on Android 16 where supported). **Stop** ends Buddy's chats and refuses phone actions from any session for a minute. **Pause** lets you use the phone in the middle of a task: the agent's next phone action waits until you tap the **Paused** pill next to the bubble (or hold the bubble and tap **Resume**), then it re-reads the screen before going on. Buddy also pauses on its own when you take the phone back: you touch the screen outside the bubble, or a call rings or starts (a phone call, or one in an app like WhatsApp or Messenger). The bubble shows it's paused, and after a call a notification offers **Resume** too; nothing resumes by itself. Touches while a question or approval card waits don't pause (the agent re-reads the screen after your answer), and neither do touches while only notification rules are running. Stop while paused ends the task without that action running, and a pause longer than 5 minutes stops the task.

### Background mode

In background mode an agent works in your apps on a screen of its own that you don't see, so you keep using your phone: your screen, your keyboard and your Back button stay yours. It goes on while the phone is locked.

- **Set up once: Settings → Background and automation → Background mode → Set up.** Android lets only the phone's own Wireless debugging make such a screen, so Buddy pairs with it, here on the phone, no computer needed. It needs Buddy's Linux (an installed agent), Developer options turned on (Settings → About device → tap Build number 7 times) and Wi-Fi. Buddy does the rest itself: it gets adb for its Linux, opens Developer options, switches Wireless debugging on, opens **Pair device with pairing code**, reads the code off that dialog, pairs, and starts a small helper. If it stops somewhere (a phone whose Settings looks different), do that step yourself and it carries on.
- **Per chat: Chat options → Work in the background**, or **New chats work in the background** on the Background mode screen. The chat's agent then reads, taps, types and opens apps on its own screen. It starts empty; the agent opens what it needs.
- **Watch it.** The chat shows a small live picture of that screen (tap it for a bigger one), and the bubble shows one while the agent works. **Show on my screen** moves the app to your real screen and the chat goes on there.
- **From the chat.** The small chip with a dot in a chat's header, on the chat screen and in the bubble, says how background mode is: green connected, red not connected (Wireless debugging went off, or the phone restarted), grey not set up. Tap it to connect again (**Start now**), set it up, pair again when the phone forgot Buddy, or switch this chat's **Work in the background**. Set-up started there says its step on that sheet and brings you back to the chat when it's done. In the bubble, a tap on the dot opens the chat with that sheet, and connects right away when the dot is red.

- **The picture by the bubble.** While the agent works there, a small live picture of its screen shows under the bubble's status line. When several agents have a screen (a chat and its sub-agents), a bar on top of the picture says whose it is and "2/7": tap its left or right half to go through them. Drag it anywhere on the screen (let go under the status line and it goes with the bubble again), and drag the grip in its bottom corner, or pinch it, to make it smaller or bigger. Drag it off a side of the screen and it becomes a tiny picture inside the status line, out of your way; tap that to bring it back. Buddy keeps its place, its size and whether it's tiny. Approval cards and questions show either way.

- **After the agent's reply** the chat's screen sleeps at once, and a minute later it closes and the apps on it with it, unless you sent the chat something new meanwhile. Until then **Show on my screen** brings what's there to you.

- **Your part comes to you.** When a step needs you on the app itself (a sign-in, a captcha, something the agent points out), Buddy moves the app to your screen and turns background mode off for that chat. Approval cards work as always.
- **Between runs the chat's screen sleeps.** An app left open and awake there would count as on screen: a messenger showing a conversation posts no notifications for it. Asleep, the app behaves as it does when your phone's screen is off, and the next run finds it where it was. While a run has a conversation open, messages that arrive come without a notification; a notification rule's run reads the conversation again before it finishes, and **Check again** in a rule's chat has the agent look at it whenever you want.
- **What's different there:** only Back, no Home, Recents or notification shade (those belong to your screen); no on-screen keyboard (text is set directly); touching your screen doesn't pause the agent, and a locked phone doesn't stop it. An app can only be in one place: one that's open on your screen moves to the background screen when the agent opens it.
- **It keeps running off Wi-Fi.** Android switches Wireless debugging off whenever Wi-Fi drops, and without more that would stop the helper too. So when the helper starts it turns on **USB debugging**: with that on, it keeps running. Leave USB debugging on.
- **After a restart of the phone** the helper is gone. Open Settings → Background and automation → Background mode → **Start now** once: Buddy switches Wireless debugging on for it (Wi-Fi must be connected). On phones that allow it, Buddy does this without showing Settings.
- **Start again after a restart** (a switch on the Background mode screen, off unless you turn it on): after the phone restarts, Buddy switches Wireless debugging on and starts the helper by itself, once the phone is unlocked and on Wi-Fi (without Wi-Fi it waits about half an hour for one, then leaves it). It tries at most three times and says nothing if it fails; the Background mode screen then shows why, and **Start now** works as before. It only works on phones that let Buddy switch Wireless debugging on by itself (the screen says so when yours doesn't), and on a Wi-Fi where Wireless debugging is always allowed: on any other, Android asks you first and Buddy leaves it to you. Wireless debugging stays on afterwards, as after Start now.
- **Accessibility back on by itself.** Android switches Buddy's accessibility service off when Buddy is force-stopped, and on some phones after an update or a crash. With background mode set up, Buddy switches its own service back on the next time it starts or you open it; other accessibility services stay as they are. On phones that gave Buddy the right to change such settings it does that itself; on the others (OnePlus, for one) it asks background mode's helper, so there it needs the helper running, which it isn't right after a restart of the phone. It doesn't when you turned Buddy off in Android's Accessibility settings yourself, and not more than once every few minutes. Where it can't, Buddy asks you to turn it on, as before.
- **While a chat works off the screen** (on its hidden screen, in the background browser, with Linux tools or thinking), a quiet notification, *Buddy is working in the background*, names the chat: tap it to open the chat, **Stop** ends the work. While an agent uses the phone's own screen, the *Buddy is using your phone* notification shows instead.
- **On the lock screen** you see only Buddy's notifications, never its bubble. An approval that arrives there has **Approve** and **Deny** on its notification, and a question its answers (up to three): Deny works as it is, the others ask for your fingerprint or PIN first.
- **Phone commands** (off unless you turn it on, on the Background mode screen): in a chat with Linux tools, the agent can run commands on the phone itself, as `adb shell` does, with the `phone_shell` tool: install and start apps, change settings, read logs and files under `/sdcard`. **Ask before each command** (on by default) shows the exact command on an approval card first. Commands that touch the screen (`input` and the like) or Buddy itself are refused: for the screen the agent has the phone tools, with their checks. That refusal only catches plain cases, since a command line can hide what it does; the approval card is the real guard. Without it, nothing stands between a tricked agent and your phone. Not available in a notification rule's run.
- **Remove** forgets the pairing and stops the helper. You can also remove Buddy under Wireless debugging → Paired devices.

How it's built: the helper is a small program from Buddy's own APK that Buddy starts over adb as Android's shell user, the only one allowed to make a display other apps can run on. It listens on this phone only (`127.0.0.1`) and asks for a secret Buddy made for it. For background mode it can do a short list of things and only on the displays it made itself: open an app or a link there, touch, press Back, take a picture; the one thing it does on your real screen is bring an app there for **Show on my screen**. It also runs a command line as the shell user, which Buddy asks of it only for Phone commands, when you turned those on. Wireless debugging itself lets paired devices control the phone; Buddy pairs only its own adb, which lives in Buddy's Linux on the phone.

### Sub-agents

For a task that splits into independent parts in different apps or sites ("compare this cable's price on three shops"), a chat's agent can start **sub-agents** with its `delegate` tool. Each sub-agent is an agent like it, on the same agent, model and Linux tools setting, and its report goes back to the agent that started it, which checks and combines them. The agent either waits for the reports or works on a part of its own at the same time and collects them afterwards.

- **As many as the task has parts,** all at the same time: Buddy sets no limit. Each one is a whole agent running on the phone and uses your plan like a chat of its own, so the phone's memory and your plan's limits are what a very large round runs into.
- **A screen only when it's needed.** A sub-agent that works in an app gets a hidden screen of its own (background mode) the moment it first uses the phone, and gives it back when it's done. One that only needs the web, files or thinking takes none: it uses the background browser and, if the chat has them, Linux tools. Without background mode set up, every sub-agent works that way.
- **You see them in the chat:** a Sub-agents box shows every screen side by side, three across, and scrolls sideways for more: a live picture of each one's screen (or of its page in the background browser), its name and its state (working, done, failed, stopped). A sub-agent with nothing to show yet has a placeholder in its card. The chat's own hidden screen is the first card, **This chat**; tap it for the bigger picture and **Show on my screen**. Tap a sub-agent to open its chat with its steps. They stay out of the Chats list. The next round of sub-agents replaces the last one's, and deleting the chat deletes its sub-agents. Tap the box's title to fold the cards away and back; they also fold while the keyboard is up, so the message box keeps its room.
- **Sub-agents only look things up.** A sub-agent gets no approval card: sending, posting, buying, deleting and changing settings are refused for it, also in apps you trust, and it can't ask you anything, schedule messages, run phone commands or start sub-agents of its own. Whatever needs your OK is done by the chat you talk to, with the usual cards.
- **If they stop with "the helper … stopped (exit 137)":** Android ended their processes. Some phones (Pixels among them) stop an app's background processes when there are many, and each sub-agent brings several. Settings → System → Developer options → **Disable child process restrictions** lets them run.
- **Stop** in the chat stops its sub-agents too, also the ones still waiting.
- **Files:** with Linux tools, each sub-agent works in a folder of its own inside the chat's work folder (`sub-agents/<its id>`), which is deleted with the sub-agent, when the next round starts or the chat is deleted.
- **An app can only be open in one place,** so the agent gives each sub-agent a different app or site.
- **Each sub-agent uses your plan** like a chat of its own, at the same time, so limits are reached sooner, and each is a whole agent running on the phone. Not available in a notification rule's run.

### Background browser

Turn on **Settings → Background and automation → Background browser**: the first time, Buddy downloads Chromium into its Linux (about 300 MB). Agents then use this browser for web pages (looking things up, comparing prices, checking a page) without taking over your screen, also while the phone is locked; for your own accounts and apps they still use the phone. It starts when an agent needs it and stops after 3 minutes unused.

- **Live view.** A chat that uses it shows the page live above the messages; tap it full screen to use it yourself, with an address bar. Touching it while the agent works pauses the agent until you tap **Continue** or write to it; using the rest of the phone doesn't hold it up. The bubble says what it's doing ("Browsing reddit.com · Typing").
- **The same approvals.** Buttons like Post, Send, Buy, Pay and Delete get Buddy's approval card, as on the phone. Agents never type into password, code or card fields.
- **Unsaved work stays.** When a page warns that leaving loses what's typed (an unsent post, a form), Buddy stays on it and tells the agent; only a second try leaves.
- **Your part, marked.** When a page needs you (a sign-in, a captcha, your details), the agent asks, and Buddy opens the browser full screen with the fields and buttons marked; it closes again when you tap **Done**.
- **Apps closing by themselves?** Android 12+ kills apps' child processes once all apps together run more than about 32, and the browser, Remote Control sessions and Termux all count. If Termux or Buddy's sessions get closed ("signal 9"), turn on **Developer options → Disable child process restrictions**.
- **Sign-ins.** To let agents use a site with your account, open the browser and sign in yourself. **Wipe browser data** clears every sign-in. "Continue with Google" often fails in automated browsers: use email and password.

### What Buddy can't do

- **Screens an app hides:** banking and payment apps, password managers and some video apps block screenshots (`FLAG_SECURE`), and some hide their content from accessibility services too: there the agent sees little or nothing.
- **Games and drawn content:** a game or a map draws its own screen without text; the agent can only look at a screenshot and tap by position, which often fails.
- **Captchas, passwords, one-time codes and payment details:** the agent hands those to you. Buddy refuses to type into a password field for an agent.
- **The lock screen:** with a PIN, pattern or fingerprint, only you unlock the phone.

### Limits

Buddy has no limit on chats, on phone actions per task or on the size of a request to an API service. The limits it does have are listed here, and each says so when it's reached: nothing is cut or dropped quietly.

- **Attachments:** 25 MB per file. Larger pictures are scaled down to 2048 px on their long side.
- **A chat's length:** a chat keeps its latest 2,000 messages (tool steps count). Past that, **Load earlier messages** brings the start back from Claude Code's or Codex's own record; with other agents a line at the top says the start is gone. The chat screen draws 150 messages at a time (**Show earlier messages**).
- **View steps:** a chat's last 3 runs, each run's latest 100 steps (the screen says how many came before), with screenshots for its latest 80.
- **What an agent reads at once:** 350 elements of a screen, 14,000 characters of a web page, and 1,500 lines or 24,000 characters from collecting a list. The agent is told each time what was left out and how to get the rest.
- **Questions to you:** 2 to 4 options, and you can always type your own answer.
- **No answer:** if an agent says nothing for 3 minutes after you send a message (15 minutes with a local model), the run ends with an error.
- **Background mode:** no fixed number of screens. **Sub-agents:** no limit on their number; the agent waits up to 8 minutes per call for their reports, then asks again. **Phone commands:** 4,000 characters and 5 minutes per command, and the last 200,000 bytes of its output.
- **Notification rules:** the hourly limit you set in the rule, one reply per run, and 30 runs waiting at once (past that a notification says who wasn't handled).
- **Messages an agent schedules:** 10 per chat, at most 30 days ahead.
- **API keys:** Codex with a service other than OpenAI's: 32 MB per request, because Buddy rewrites those requests. Everything else goes on as it is; the service's own limit applies.

## Linux tools: building apps

Each chat has its own **Linux tools**, off by default. With them on, the chat's agent may run commands in Buddy's Linux (including installing packages with `apk`) and create or edit files in `~/.buddy/work`. Turn them on with the **Linux tools** chip under the chat's title (a sheet says what that allows first) or with the switch in **New chat**; the chat's next message gets them, and turning them off again is one tap. Settings → Safety and approvals → **Linux tools in new chats** sets what new chats start with; it also decides whether your own sessions outside Buddy's chats may install apps. With the bundled **android-app** skill (plus `AGENTS.md` for Codex) you can ask *"make me a calculator app"*: it sets up a toolchain the first time (OpenJDK, aapt2, d8, apksigner; about 400 MB), writes plain Java, builds a signed APK on the phone without Gradle, and opens Android's installer for you to confirm. The first time, Android asks you to allow Buddy to install apps.

Standing instructions of your own for Codex, OpenCode, Antigravity and Grok can go in `~/.buddy/work/AGENTS.md`: Buddy only updates its own part of that file, between its `buddy:start` and `buddy:end` markers, and keeps the rest.

Turn them on only in the chats that need them: with Linux tools on, text on screen that tries to trick the agent could lead to commands being run.

- **GitHub (Settings → Agents and models → GitHub):** sign in once with GitHub's own device code: Buddy installs git and the GitHub CLI, signs gh in to your account and sets git to your name and private noreply email. Agents in chats with Linux tools can then clone, commit, push and open pull requests as you; they're told to ask you before anything they push or post. **Sign out** takes the access away.

## Security in detail

- **Local only.** The MCP server listens on `127.0.0.1` and requires a random per-install token. Nothing is reachable from the network.
- **Approval gate.** The agent is instructed to call `confirm` before sending messages, posting, buying, deleting or changing settings. You see the exact action with **Approve / Change / Deny**. When the agent needs you to choose (which reply, which item), it can call `ask` instead: a card with 2–4 answers and your own typed answer. When there's a step only you can do (a password or code, your details in a form, a file picker, a captcha), `ask` can mark the fields or buttons on the screen and wait next to the bubble while you do it; `point_out` shows where something is. The marks (a box, circle or arrow with a short label) are drawn over the app without blocking your touches, and turn green and go once you do what they point at (tap that button, flip that switch, fill in that field). Ask "show me how to…" and the agent guides you one step at a time, waiting for each tap instead of doing it for you.
- **App permissions (enforced by Buddy, not the agent).** Settings → Safety and approvals → App permissions, per app:
  - **Trust:** asking is left to the agent.
  - **Hard:** Buddy itself checks every tap; buttons like Send, Pay, Delete (built-in words in all of Buddy's languages, plus your own *always ask* / *never ask* rules, with suggestions from buttons the agent has tapped) need your OK. So does pressing Enter after typing, since in most fields that sends what was typed; not in an app's own search field, where Enter only looks something up (a web page, a browser and a banking app still ask).
  - **Smart:** the rules, then a separate temporary Claude Code or Codex session without tools reviews every other tap against your request and the screen (about 3 s a tap). OpenCode, Antigravity and Grok chats are reviewed by Claude Code or Codex.
  
  Messaging, social, email, calling, shopping and money apps start on Hard, and so do Settings, permission screens, installers and app stores, whatever you chose at setup. In those, unless you set the app to Trust yourself, every button of a permission dialog or installer asks, and so does every switch in Settings. An approval covers the action it was given for and waits five minutes for it: an OK for sending a message isn't spent on a Pay, Buy or Delete button, and if the screen changed while the card waited, the tap isn't made. The agent can never tap or type in Buddy's own bubble, cards or settings, so it can't approve for you or loosen the rules. A switch for testing, **Let agents tap Buddy's screens** (Settings → Safety and approvals, off unless you turn it on), opens the Chats list, a chat and the main Settings screen to agents. Everything that decides what an agent may do stays yours with it on too: the bubble, approval cards, a chat's Linux tools chip, Chat options and its scheduled task, and the screens for App permissions, API keys, MCP servers, Notification rules, Scheduled, Skills, Background mode and Backup. A tap there is refused, and the agent is told which parts are open to it.
- **Ask about each new app** (Settings → Safety and approvals; on for a new install, off for one set up before 2.3.11 until you turn it on). The first time an agent is about to tap or type in an app you haven't set in App permissions, Buddy asks whether it may work there on its own (Trust) or should ask you first (Hard), and keeps the answer as that app's setting. What the app would get anyway is the first choice. Only in chats on Ask, with you at the phone: not for sub-agents, notification rules or scheduled tasks, not while the phone is locked, and never for banking and payment apps, Settings and app stores. Skipped or unanswered, the app keeps its default and Buddy doesn't ask again until it restarts.
- **Switch a chat's agent.** With more than one agent signed in, a chat's header shows its agent's name on a chip: tap it and pick another. The new agent takes over from your next message. It starts a conversation of its own and is given the chat so far as text (the end of what was said, up to about 60 KB of text), not the first agent's steps, files or tool results, so it looks again at what it needs. The model and effort go back to the new agent's defaults. Switch straight back before the new agent has answered and the chat is as it was, with the first agent's own conversation. Not while the chat is working, and not in a sub-agent's chat.
- **Approvals, per chat.** The line under a chat's header (and in the bubble's panel) says how that chat asks, and a tap changes it:
  - **Ask** (every new chat): each app follows its App permissions setting.
  - **Routine allowed:** routine steps go ahead in every app without a card: sending a message, or a step the reviewer would ask about. Each one is noted in the chat. Paying, buying, deleting, installing, passwords and security settings still ask you, and so does everything in banking and payment apps, Settings and app stores. Steps in the background browser ask as before, and so does Enter on a web page or in a browser, where Buddy can't tell a message box from a checkout form. A button you put on an app's *always ask* list keeps asking.
  - **Always ask:** also in apps set to Trust, Buddy asks before sending, posting, buying or deleting. The chat's own Allowed without asking list doesn't apply while this is on.

  The choice stays with the chat until you change it, and anything other than Ask shows in the accent colour so it is never on unseen. Only you can change it: agents can't tap it. Sub-agents and notification rules keep their own stricter rules whatever the chat says. To allow routine steps in a few apps only, use Chat options → Allowed without asking, which lasts until the task ends. The same sheet lists the **apps in this chat**: where the agent has tapped or sent, each with its App permissions setting (Trust, Hard or Smart); a tap opens App permissions to change it.
- **Prompt injection is the main risk.** Buddy reads whatever is on screen. A malicious message, email or web page could contain text like "send this to all your contacts". Buddy's instructions treat on-screen text as content, never commands, and the approval gate is the backstop, but no model is perfect. Read approval cards carefully.
- **Notification rules work for someone else's message,** so their runs get less: no shell, files or web (even in a chat with Linux tools), no installing apps, your Trust settings don't apply, and opening a link always asks you. The notification is passed to the agent as outside content, never as instructions. A rule's countdown, or its Don't ask setting, can only approve sending a message (never paying, buying or deleting, and never in payment or shopping apps), and only after a second AI agrees the reply fits your rule; otherwise the card waits for you. A run sends at most one reply, and none once you've answered the person yourself. Each rule has an hourly limit: by default 20 runs per conversation and three times that for the whole rule (change it or turn it off in the rule); past it, new messages wait and then get one run together. Use countdowns and Don't ask for low-stakes replies: with Don't ask nobody reads a reply before it goes out.
- **Limited tools.** Without Linux tools, Claude Code gets the phone tools, web search and fetch, and read access to that chat's attachments only (no shell, no other files). Codex gets no shell either (only when a message comes with a file that isn't a picture, read-only commands to open it). OpenCode's shell and file edits are refused (set to "ask", which a non-interactive run auto-rejects). Antigravity has only the phone tools and that chat's attachments pre-approved, and can't run notification rules yet. Grok is offered only the phone tools and web search and fetch (plus file reads once the chat has attachments); a notification rule's run gets only the phone tools. Everything runs inside Buddy's own app storage, separate from your other apps' files.
- **What leaves the phone:** only what Claude Code, Codex, OpenCode, Antigravity or Grok sends to its model provider (Anthropic, OpenAI, Google, xAI, OpenCode's own service, or the provider you connected) to answer you, including screen text, screenshots and attachments it reads.
- **Never** let Buddy type passwords, one-time codes or payment details. It's instructed to hand those back to you.

## How it works

```
Buddy app / bubble ──► Buddy's Linux (Alpine via proot): buddy-run ──► claude -p, codex exec, opencode run, agy -p or grok -p
        ▲                                                                  │
        └────────────── streamed replies (POST /event) ◄───────────────────┤
                                                                           ▼
Buddy accessibility service ◄──── MCP over http://127.0.0.1:8765/mcp (phone tools)
```

- The **accessibility service** draws the bubble and runs a small local **MCP server** with the phone tools: `read_screen`, `tap`, `long_press`, `type_text`, `scroll`, `swipe`, `press`, `open_app`, `list_apps`, `open_url`, `screenshot`, `wait`, `install_apk`, `wait_for_install`, `confirm`, `ask`, `point_out`, `notify`, `reply_notification` and `update_buddy`.
- **Typing on web pages** (Chrome, apps' web views) goes in as a paste, so page editors keep it; your clipboard then holds that text.
- **Tips per app.** When an app or site costs an agent time (a button that needs a second tap, a field that only takes a paste), it can note that in `~/.buddy/tips/<app or site>.md` in Buddy's Linux. Buddy shows the note the first time that app or site comes up in a chat. The notes stay on your phone; delete them there if you like.
- **Buddy's Linux** is a small Alpine Linux that Buddy downloads into its own storage (4 MB) and runs with [proot](https://proot-me.github.io/), which ships inside the APK. Claude Code installs there with Anthropic's official installer, Antigravity with Google's, Grok with xAI's; Codex and OpenCode from npm.
- Your message goes to the agent in Buddy's Linux, which uses those tools and streams its progress back to the app.
